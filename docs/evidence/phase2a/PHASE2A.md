# Phase 2a evidence: deterministic corpus and policy substrate

Scope: generator, canonical artifacts, policy (Postgres RLS and an independent Python
oracle), case plan and split. There is no gateway, no model execution and no harness in
this phase.

Everything below was run locally on macOS arm64, with Postgres 17.11 (`postgres:17`
container, linux/arm64 under Colima) and Python 3.11.17, 3.12.13, 3.13.16 and 3.14.8.

## Closure run (two fresh containers)

1. Seed 7 at default scale (34,625 POs, 103,913 PO lines, 248 documents, 801 chunks) was
   built with `eeb build` on a brand-new container.
2. That container was destroyed and the build was repeated on a second brand-new container.

**Results:**
- The two 281-file instances are byte-identical (instance digest `c92995e1…`).
- Each passed: reload byte-identity, 0 disagreements, 0 hardening problems, and 29 of 29
  SQL gold facts reproduced by `gold_sql`.
- Authorization digest on both containers: `eb4ac67d…` (database = oracle = recorded).
- `eeb verify` of instance A on container B also passed.

Record: `fresh_container_closure.json`.

## Falsifiability: planted policy mutants

The agreement check is credible only if a bug in either implementation shows up.

**Detected as a disagreement**

| Implementation | Mutant | Detected by |
|---|---|---|
| SQL compiler | assignment window ignores `valid_to` | agreement (`cm_moved` sees MRO) |
| SQL compiler | `eq_param` → TRUE | agreement |
| SQL compiler | `in_parent` → TRUE | agreement |
| SQL compiler | `in_values` → TRUE | agreement |
| SQL compiler | role membership ignores validity | agreement (leaver privileged) |
| SQL compiler | column grant widened to table grant (contacts) | agreement (columns) |
| SQL compiler | RLS disabled on `purchase_orders` | agreement **and** hardening |
| SQL compiler | **both** login-binding layers removed (policy clause and assignment-table RLS) | agreement |
| Oracle | assignment window ignores `valid_to` | agreement |
| Oracle | NULL foreign key treated as a visible parent | agreement |
| Oracle | `in_values` ignored | agreement |
| Oracle | `*` columns collapsed to primary key | agreement |
| Oracle | privilege ignores assignment activity | agreement |

**Detected by hardening only**

| Implementation | Mutant | Why |
|---|---|---|
| SQL compiler | `FORCE ROW LEVEL SECURITY` dropped on `budgets` | Not visible through any principal's reads (the owner is the superuser admin), so `hardening_checks` must and does catch it |

**Masked by redundant enforcement (not counted as kills, not equivalent)**

| Mutant | Outcome |
|---|---|
| Policy clause `login = current_user` removed alone | No change: assignment-table RLS still binds rows to the login (finding F-3) |
| Assignment-table RLS removed alone | No change: the policy clause still binds |

The paired removal of both is in the first table and is detected.

**Equivalent on the validated domain (not run)**

- `eq_param` as `IS NOT DISTINCT FROM`: parameterised assignments are validated non-null,
  so NULL = NULL never arises.

**Totals:** 14 planted mutants, all detected (13 by agreement, 1 by hardening only).
2 single-layer deletions masked by redundant enforcement.

## Test suite

Each interpreter (3.11, 3.12, 3.13, 3.14) passes 158 tests, with the Postgres fixture
required (`EEB_REQUIRE_PG=1`) and the slow default-scale test included. `ruff` and
`mypy --strict` are clean.

## Implementation findings

See `docs/FINDINGS.md`:
- **F-1:** stale PO index with several S2 suppliers. Fixed; the regression test is shown to
  fail on the old code.
- **F-2:** a role switch is denied by privilege before RLS, so the RLS tests are split out.
- **F-3:** redundant login binding.
